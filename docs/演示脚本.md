# 演示脚本（30 分钟盲跑版，验收 A14）

目标：面试官/陌生人照本文件从上到下敲，不需要任何额外口头知识，也不会遇到未记录的手工步骤。
全程离线（默认 `LLM_PROVIDER=template`），不联网、不需要密钥、不需要起服务。

## 0. 准备（约 2 分钟）

```bash
cd <仓库目录>
python -m venv .venv                 # Windows: py -3.12 -m venv .venv
.venv/Scripts/activate               # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
copy .env.example .env               # 不改任何值也能跑完（待填项只影响外部模型路径）
python -m pytest tests/ -q           # 期望：全部通过，无缺依赖
```

预期：pytest 全绿（约 170 条用例，几秒内跑完）。若 `pip install` 失败，先看是否用了 Python 3.11+
（方案 §五 要求 3.11+；本机实测 3.12.8）。

## 2. 演示主链路（约 8 分钟）

```bash
python -m src.cli --demo --fresh-audit --rebuild
```
11 轮固定演示（源码：`src/cli.py::DEMO_TURNS`）。逐轮要看到的关键点：

| # | 输入 | 你要指给对方看的 |
|---|---|---|
| 1 | `订单 ORD-2026-000101 实付多少钱？` | 金额来自 SQL（987.00元），`工具=query_order[ok]`，依据是 `tool:query_order#<hash>` |
| 2 | `这个订单能退吗` | 指代消解生效（沿用上一轮单号）；引用 `POLICY-RETURN@v2` 并带出处/有效期 |
| 3 | `你能保证全额退款吗` | 门禁动作 `block_commit + explain_only`；回答里没有「保证/已为您」；给了人工出口 |
| 4 | `那我不要退款了，给我赔偿 100 元行不行` | 用户要的「100 元」**没有出现在输出里**（生成前就被剔除，不是事后删） |
| 5 | `ORD-2026-000111 物流到哪了` | 轨迹/异常件是工具读数；`运单 YD…`，状态「异常件」 |
| 6 | `这都延误了，我要投诉，你们得赔` | `force_handoff`，`紧急=True`，`⟨本轮已自动转接⟩` |
| 7 | `退款多久到账` | 只引用规则区间（微信 1 工作日／储蓄卡 1-7／信用卡 1-15），并声明「不构成对具体时刻的承诺」 |
| 8 | `转人工` | 用户要人就给，不设障碍（F-009） |
| 9 | `SKU-FAN-Z9 华南有货吗` | 库存 0 件如实说「无货，补货时间我无法确认」，不承诺补货 |
| 10 | `那就给我留一件，我明天买` | 锁库存请求被当作承诺索取处理；输出无「已为您预留」 |
| 11 | 重复第 1 轮输入 | `⟨重放命中，结论一致⟩` —— 幂等键生效（第 6 轮 `demo-6` 与 `demo-1` 同输入不同会话也会各自判定） |

## 6.5 服务编排演示（约 5 分钟，可选但推荐）

```bash
python -m ops.cli check                            # ① 预检：端口/配置/目录可写，不动任何进程
python -m ops.cli start --smoke --port 18081       # ② 一键启动：起进程 → 健康确认 → 真打一发
python -m ops.cli status                           # ③ 运行中（PID + 健康详情）
python -m ops.cli start --smoke --port 18081       # ④ 再点一次：先全部停止再按序重启，不会双绑端口
curl -s -X POST http://127.0.0.1:18081/v1/chat -H "Content-Type: application/json" ^
     -d "{\"text\":\"你能保证全额退款吗，订单 ORD-2026-000103\",\"session_id\":\"demo\"}"
python -m ops.cli logs api -n 20                   # ⑤ 停机前把现场留出来
python -m ops.cli stop --port 18081                # ⑥ 一键停止 + 三项残留校验
python -m ops.cli status                           # ⑦ 回到「未运行」，后台不留进程
```

要指给对方看的三件事：

1. 第 ④ 步不会因为端口已被占用而崩，也不会出现两个实例——它先停后起；
2. `start --smoke` 证明「进程在」等价于「能答」，且 `/v1/audit/<key>` 能反查到规则版本；
3. `stop` 的输出里必须同时出现「已停止 / 端口已释放 / 无孤儿进程」三行，缺一项就算失败。

失败面也当场演示一次（不启动任何东西）：

```bash
python -c "import socket,time; s=socket.socket(); s.bind(('127.0.0.1',18085)); s.listen(1); time.sleep(20)" &
python -m ops.cli start --port 18085        # 另开一个窗口执行
```

预期：报「端口被其它进程占用」并给出查占用方的命令，**且不留下 `run/api.json`、不启动任何进程**。
演示完那个占端口的进程自己会退出（20 秒），编排器不会去杀不属于它的进程。

## 手工步骤核对（A14 自检）

本脚本用到的动作只有：`cd` / 建 venv / `pip install` / `copy .env.example .env` / `python -m …` /
`python scripts/…` / 只读 SQL 查询 / 由编排器起停**本项目自己的**子进程（`ops.cli`，用完即停）。
演示结束时必须回到 `python -m ops.cli status` 显示「未运行」，后台不留进程。**没有**：手工改数据库、手工补文件、手工设置环境变量、
需要登录的外部平台、需要密钥的调用。第 1 步的 SQL 查询是可选的（用来看视图），
不查也不影响后续任何步骤。

时长为纸面分段估计（含 6.5 节约 35 分钟），**计时未实测**——按方案要求标注为设计值，见 `docs/口径声明.md`。
编排层的单次操作是实测的：启动到 ready 0.6s；一次优雅停止在 1s 内完成（含端口释放与孤儿进程校验）。
