# 意图体系（F-002）：3 个一级 / 20 个二级 + 高危意图集 + JDDC 映射

数据文件：`data/intents/taxonomy.csv`（体系本体）、`data/intents/jddc_label_map.csv`（JDDC 侧映射留证）。
机检：`tests/test_intents.py`、`tests/test_data_contracts.py`、`scripts/verify_jddc_mapping.py`。

## 一、为什么先做体系而不是先做模型

方案的命题是「合规门禁可审计」。要让「重大事项只解释不确认」（F-008）可测试，
必须先有一份**能判对错**的意图口径：哪些问询属于重大事项，必须是表里的行，
而不是模型每次现编的判断。所以意图判定用**关键词权重的确定性规则**实现：

- 可复跑：同一句话永远同一个结果（评测归因不被随机性污染）；
- 可变异：`M9` 之类「把某个判定分支关掉」的缺陷注入能立刻让用例变红；
- 可审计：`IntentPrediction.matched` 把命中的词全部落进审计日志，反查「为什么判成高危」。

代价也写清楚：规则分类器对长尾说法覆盖不足，**意图 Top-1 实测 90.6%**（见评测报告），
不是模型水准；换 LLM 判定会把红线用例的可复现性一起换掉，这条不划算。

### 高危意图集（4 个）与它的判定口径

`{REFUND_CONFIRM, COMPENSATION, PRICE_PROTECT, COMPLAINT_ESCALATION}` —— 对应方案 F-002 点名的
**退款、赔偿、价格承诺、投诉**四类。命中即走「只解释 + 强制转人工」（F-008），并由承诺白名单
在**生成前**剔除承诺类别（F-010）。

高危不是只有这一条路：**诱导句式**（`你能保证…`、`你替我确认`、`给个准话`、`你就说能退`、
`不说话就当…`）无论业务意图落在哪，都会把本轮升级为「承诺索取」并按 F-010 处理。
实现见 `src/intents.py::PROMISE_INDUCEMENT` 与 `data/gates/committal_lexicon.csv`。

第三条路径是**条文自证**：所引条款里出现「核定/坐席/人工受理/由人工」且本轮涉及具体订单时，
门禁补一条 `G-008-adjudication-required` 强制转人工（`src/gates.py:297`）。

## 五、体系变更的约束

`taxonomy.csv` 是 `Ruleset.version` 哈希的一部分：**改意图体系 = 改门禁规则版本**，
审计日志里每轮的 `ruleset_version` 会变。这不是副作用，而是设计——评测判据冻结后
（方案 §六：P4 必须在 P3 判据冻结后启动）任何改体系的动作都会留下版本痕迹，可反查。

列完整性由 `tests/test_data_contracts.py` 把守：每行必须 8 列、槽位取值合法、
高危集合恰好是那 4 个。这一条是被真实事故逼出来的——体系文件一度把带槽位的行写成 9 列，
导致 `required_slots/needs_handoff` 整体错位、槽位索取静默失效，而所有旧用例仍然是绿的。
