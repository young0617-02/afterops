# 退货上门取件预约

- 验证时间：2026-11-10
- 范围：退货批准后，顾客可在 7 天内预约上门取件时段；待上门前顾客或店主可取消；店主标记揽收后自动写入退货运单与「已揽收」物流事件，后续沿用现有回寄物流推进
- 迁移：`d3f5a7c9e1b4`（`return_pickups`）

## 行为

1. 新表保存退货单、顾客、取件单号、状态（`scheduled`/`picked_up`/`cancelled`）、预约日期、时段、订单收货地址快照、承运商、取消原因与各状态时间；同一退货单可保留多条历史预约，但同时只能有一条待上门。
2. 只有「已批准、未登记回寄单号、无待上门预约」的退货可预约；日期不能早于今天、最多 7 天内，时段限定 `09:00-12:00`、`13:00-18:00`、`18:00-21:00`。
3. `POST /api/store/returns/{id}/pickup` 创建预约（模拟分配顺丰速运），写审计并通知员工；`.../pickup/cancel` 顾客可取消待上门预约，退货保持已批准，可重新预约或自行寄回。
4. `POST /api/admin/returns/{id}/pickup/picked-up` 标记揽收：取件单转已揽收，写入承运商与取件单号作为退货运单，退货进入 `in_transit`、物流状态 `picked_up`，追加「已揽收」事件并通知顾客；之后可按现有流程推进运输/派送/到仓。
5. `POST /api/admin/returns/{id}/pickup/cancel` 店主可填写说明取消预约并通知顾客；取消后顾客可重新预约或自行登记回寄。
6. 已有待上门预约时，顾客不能登记自寄单号；有待上门预约时后台不能确认收货，需先揽收或取消，避免预约与收货状态交叉。
7. 退货视图新增 `pickup` 与 `can_schedule_pickup`；后台 `/api/admin/returns?status=pickup` 只返回待上门预约，计数新增 `pickups`。
8. 顾客售后卡展示预约表单、日期/时段、取件地址、取件单号与取消按钮；后台退货卡展示取件信息，店主可标记揽收或填写说明取消。

## 边界

- 承运商为模拟分配（顺丰速运），不接真实取件下单/快递员接口；揽收由店主手动确认，无自动回调。
- 时段固定三档、最多预约 7 天；不支持修改已预约日期（需取消后重约）、取件费用、超时未上门自动提醒或改约次数限制。
- 取件地址使用下单收货地址快照，不支持单独编辑取件地址或选择地址簿。
- 预约不产生退货运费差异，运费仍按退货政策在退款时统一扣除。
- 取件单在待上门状态不会自动过期，需顾客/店主取消或店主揽收。
- 取件预约信息未进入 AI 退货进度回复；AI 仍按退货单状态回答「待回寄」。
