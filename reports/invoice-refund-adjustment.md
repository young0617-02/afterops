# 发票与退款联动

- 验证时间：2026-11-09
- 范围：订单退款后发票金额与净支付不一致时，后台与顾客展示「需重开」；退款后申请发票按净支付开票
- 迁移：无（读取现有发票、订单与退款账本）

## 行为

1. 顾客申请发票时，开票金额改为「订单应付 − 已执行退款」；全额退款订单不能再申请发票（409）。
2. 发票视图新增 `net_paid_cents` 与 `adjustment_required`：待处理/已开票且发票金额不等于当前净支付时标记需重开；已作废/已驳回不标记。
3. 后台财务发票卡展示「需重开」、发票金额与当前净支付；顾客订单发票区展示「退款后需重开」、发票金额与当前净支付。
4. 仍沿用既有「作废 → 顾客重新申请 → 店主重新开票」流程，不自动作废或自动红冲；作废后标记消失，重新申请按最新净支付生成金额。
5. 退款原因/状态与发票状态各自独立；补偿不计入净支付，不会触发发票需重开。
6. 列表查询批量汇总每个订单的已执行退款，避免逐张发票查询造成 N+1。

## 边界

- 不自动作废、不自动生成红字发票、不自动重开；仍需店主人工操作与顾客重新申请。
- 不接税务系统，不生成 PDF/电子回单，不支持部分红冲、按行项目开票或多张发票拆分。
- 只比较发票总额与订单净支付；不处理优惠券、运费、补偿等科目的单独开票口径。
- 已驳回/已作废发票不提示需重开；历史发票记录继续保留。
- 退款到账与发票状态无联动轮询，状态来自内部 mock 账本。
