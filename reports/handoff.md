- 入口：顾客聊天窗；`/admin` → 人工工单
- 迁移：`4d79ad0ee5d2`（`handoff_tickets`）

## 流程

1. 顾客发送「转人工」或触发高危/承诺索取，且本轮没有生成资金/地址提案时，创建 `handoff_tickets`。
2. 同一会话存在活动工单（`open` / `claimed`）时复用并更新最近消息，不重复建单。
3. 退款/改地址/补偿等提案走提案审批队列，不重复创建人工工单。
4. 后台可查看工单摘要与完整会话、接管工单、填写处理说明并标记解决；解决后会话状态置为 `closed`。
5. 工单创建、接管、解决分别写 `handoff_created` / `handoff_claimed` / `handoff_resolved` 审计事件。

## 边界

- 同一会话最多一个活动工单；解决后再次转人工会创建新工单，不支持重开。
- 无自动分配、优先级、SLA、超时提醒、坐席在线状态；只有站内队列。
- 无短信/IM/邮件通知，客服需要主动查看后台。
- 顾客端只能看到聊天中的工单号，不能查询工单进度；无附件/凭证上传。
- 工单详情展示完整会话文本，未做导出与脱敏导出。
