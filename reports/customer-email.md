# 顾客邮件通知

- 验证时间：2026-11-04
- 范围：顾客通知邮箱设置、分类邮件偏好、业务通知转邮件、outbox 投递、停用
- 迁移：`962c3bf311fd`（顾客邮件偏好）
- 投递目标：本机 Mailpit（`mailpit:1025`），收件人为顾客本人邮箱

## 流程

1. 顾客可在结算页填写通知邮箱，或在「售后进度 → 通知邮箱」保存/停用，并分别开关发货/物流、售后/提案/工单、退货/换货三类邮件。
2. `PATCH /api/store/me` 校验格式、统一小写，并按商家校验唯一性；传空字符串表示清除；偏好字段可单独更新。
3. `notify_customer` 在写站内通知的同一事务内，如果顾客有邮箱、总开关开启且对应分类偏好开启，写入 `outbox`（`customer_notification_email`）。
4. worker 通过现有 SMTP 通道投递，失败按退避重试，超过上限置 `failed`；后台「邮件投递」可查看与重试。
5. 邮件正文包含业务事件正文、站内详情链接与停用说明。

## 覆盖的顾客事件

- 提案执行 / 提案驳回
- 退货通过 / 退货驳回 / 退货签收
- 运单创建 / 物流节点更新
- 人工工单解决
- 订单自动完成

以上事件同时保留站内通知。

## 边界

- 与客服邮件共用 outbox，投递为 **at-least-once**，崩溃可能重复发送。
- 邮箱未做验证（不发确认邮件），顾客可能填错；不是登录凭据。
- 只有本地 Mailpit，未接生产 SMTP、退信处理、投诉/退订合规流程。
- 偏好只有发货/售后/退货三类粗粒度开关，不做到单个事件类型；停用邮件即清空邮箱，分类偏好保留。
- 邮件模板为纯文本，无多语言、附件、品牌样式。
- 失败重试需人工在后台触发；单 worker 消费。
