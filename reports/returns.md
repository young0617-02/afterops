# 退货申请与回寄

> 后续更新：聊天已可直接创建待审核退货/换货申请；顾客也可撤回待审退货并补充凭证；换货已支持同价/更低价的其他 SKU 与差价退款。见 [chat-return.md](chat-return.md)、[return-self-service.md](return-self-service.md)、[cross-sku-exchange.md](cross-sku-exchange.md)。本页验证数字与边界为当时快照。

- 验证时间：2026-11-03
- 范围：已签收订单 → 退货申请 → 店主审批 → 顾客回寄 → 店主收货 → 退款提案审批
- 迁移：`c8d332de336e`（`return_requests`）
- 入口：顾客 `/after-sales` → 退货；后台 `/admin` → 退货

## 状态流转

| 当前 | 操作方 | 去向 |
|---|---|---|
| 处理方式 | 顾客申请 | `refund` 退货退款 / `exchange` 同款换货 |
| 待审核 `requested` | 店主批准 | 待回寄 `approved`，写入配置的退货地址 |
| 待审核 `requested` | 店主驳回 | 已驳回 `rejected`，记录原因 |
| 待回寄 `approved` | 顾客登记回寄 | 已寄回 `in_transit` |
| 待回寄/已寄回 | 店主确认收货（退款） | 已收货 `received`，生成待审批退款提案 |
| 待回寄/已寄回 | 店主确认收货（换货） | 已收货 `received`，生成零元替换订单并占用库存 |

- 只有已签收/已完成且支付状态为 `paid`/`partially_refunded` 的订单可申请。
- 同一订单同时只能有一个进行中的退货申请。
- 退款收货后调用现有退款提案服务生成 `refund_proposal`，资金仍由店主二次审批，不自动退款。
- 换货收货后复制原订单明细/收货地址，生成零元 `paid/unfulfilled` 替换订单，占用库存并进入现有履约发货；不生成退款提案。
- 退货申请、批准、驳回、回寄、收货均写哈希链审计；新申请/回寄会触发客服站内通知与 outbox 邮件。

## 边界

- 换货仅支持同款同数量、不换 SKU/不补差价；替换订单为零元订单，走现有履约发货。
- 无退货物流 API、无质检/部分退款金额规则；退货地址为配置值（`RETURN_ADDRESS`）。
- 退货审批与退款审批分离；确认收货不会自动退款。
- 顾客登记回寄后不能自行修改单号；无附件/凭证上传。
- 退款提案被驳回后不会重新打开退货；需要人工另行处理。
- 客服只读；退货审批与确认收货为店主权限。
