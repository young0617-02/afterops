# 退货资格政策

- 验证时间：2026-11-05
- 范围：店主配置全局退货窗口、类目窗口、禁退类目、换货开关；资格按订单商品逐件计算
- 迁移：`580caaf644e6`（`return_policies`）、`b9c1e3d5f7a0`（类目窗口）

## 行为

1. 每个商家一条退货政策，默认签收后 **7 天**、允许换货、无禁退类目、无类目窗口；未保存时按默认值执行。
2. 店主在后台「退货」页设置全局可退天数（0–90）、类目窗口（每行「类目=天数」，最多 20 个，类目唯一、0–90 天）、退货运费、禁退类目与换货开关；客服只读。
3. 类目窗口优先于全局天数；未配置的类目使用全局天数。禁退类目按商品当前类目匹配。
4. 政策变更写 `return_policy_updated` 审计，payload 包含修改前后值（含类目窗口）与操作人。
5. 顾客售后页调用 `GET /api/store/returns/eligibility`，返回订单级默认窗口/截止与每件商品的 SKU、类目、窗口、截止、是否可退及原因；不可退商品复选框禁用并显示原因。
6. 部分退货可只勾选仍可退的商品；前端默认只勾选可退商品。`POST /api/store/returns` 与聊天退货都按所选商品逐件校验，绕过前端也会被 409 拒绝。
7. 校验顺序：订单已签收 → 支付状态可退 → 无进行中退货 → 每件商品非禁退类目 → 每件商品未超类目窗口；换货还要求商家开启且整单商品均可退。
8. 截止时间取运单 `delivered_at` + 该商品类目窗口；缺少签收时间时提示联系人工，不再无窗口放行。
9. 帮助中心展示全局窗口、类目窗口、禁退类目与运费概要。

## API

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/store/return-policy` | 顾客登录 | 当前商家政策（含类目窗口） |
| GET | `/api/store/returns/eligibility?order_no=&resolution=` | 顾客登录 | 订单级与逐件资格、截止日、禁退 SKU |
| GET | `/api/admin/return-policy` | 店主/客服 | 后台读取 |
| PATCH | `/api/admin/return-policy` | 仅店主 | 保存全局窗口、类目窗口、运费、换货开关、禁退类目 |

## 边界

- 窗口只支持按商品当前类目配置，不支持会员等级、促销活动、单商品或订单单独窗口；商品改类目会影响历史订单判断（非下单快照）。
- 禁退只按类目，不支持按 SKU/品牌/单商品配置。
- 换货开关只控制换货，关闭后退货退款仍可用；没有单独换货窗口/次数限制。
- 类目窗口最多 20 个、类目名 ≤40 字；没有类目下拉联想，需手输与商品类目完全一致。
- 无节假日顺延、按责任方判定、折旧/手续费、保修维修合并；退货运费仍是固定金额。
- 不接真实物流签收回调，签收时间仍由店主在履约页推进节点产生；已签收但缺签收时间的订单现在会提示联系人工。
- 不发送政策变更通知，顾客下次打开售后页或帮助中心时看到新规则。
