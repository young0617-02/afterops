# 维修报价与顾客支付

- 验证时间：2026-11-10
- 范围：店主收到维修件后可发送维修报价；顾客接受/拒绝报价，接受后可通过 mock 支付维修费；未确认或未支付时不能完成维修
- 迁移：`f5a7c9e1b3d5`（`repair_requests` 报价与支付字段）

## 行为

1. 维修单新增报价金额、报价状态（`none`/`pending`/`accepted`/`declined`/`paid`）、报价说明、报价/响应/支付时间与支付引用。
2. 店主仅可对「已收货」且尚未报价的维修单报价，金额必须大于 0、说明必填（最多 1000 字）；同一维修单不能重复报价。
3. 报价后顾客收到站内通知，可在售后进度中接受或拒绝；接受后进入待支付，拒绝后商家按原样寄回，仍可完成维修单。
4. 顾客接受后调用 mock 支付接口，生成 `RPQ-` 支付引用并记录支付时间；未支付不能完成维修。
5. 店主完成维修时校验：报价为待确认/待支付时拒绝完成；已支付、已拒绝或未报价（免费维修）可正常完成并寄回。
6. 报价、接受、拒绝、支付分别写审计 `repair_quote_issued` / `accepted` / `declined` / `paid`；报价通知顾客，响应与支付通知员工。
7. 维修视图与接口返回全部报价字段；顾客售后卡展示报价、状态、说明、支付单号与操作按钮；后台维修卡展示报价并可发送报价。
8. 支付为系统内 mock 记录，不接真实支付渠道，也不生成订单退款或发票。

## 边界

- 支付为 mock 记录，不接真实支付渠道，不产生支付流水对账或退款；拒绝报价不产生任何退款。
- 每张维修单只能报价一次，不支持改价、重新报价或报价超时自动关闭。
- 报价不改变维修单主状态，仍停留在「维修中」；只有完成维修才进入「维修寄回中」。
- 顾客拒绝报价后不会自动生成退回流程；仍需店主填写处理结果与寄回运单完成维修单。
- 维修费不进入订单支付/退款/发票体系，也没有维修成本、毛利或财务对账。
- 不支持部分支付、分期、支付失败重试或渠道回调。
- 报价与支付信息未进入售后统一时间线（时间线当前只读维修主事件）。
