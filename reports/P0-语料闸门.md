## 四、与方案文本的两处不一致（按真实证据更正，不顺着写）

1. **方案 F-001 与 §十 写「JDDC … CC BY 4.0」——不成立。**
   论文页脚是 **CC-BY-NC**（ELRA 对 *论文章节* 的许可），而**数据集本身**的许可条款在发放页（现已失效）里，
   论文正文没有给数据集的再分发许可。方案 §十 把「论文页可核对」写成了「规模与 CC BY 4.0 已复核」，
   其中 CC BY 4.0 这一项来源错位（错把 ACL Anthology 对论文的 CC BY 4.0 当成了语料许可）。
   → 影响：作品集若要引用语料样例，应按 **NC（非商业）** 处理，并且**在拿到官方条款页之前不把许可写成结论**。

2. **F-002 假设「JDDC 意图标签」是一份可枚举的小集合——实际是 289 类。**
   方案要求映射到自有 3 一级 / 15–20 二级体系。289 → 20 的映射需要原始标签清单，
   而清单在数据文件里（当前拿不到）。因此本仓库的 `data/intents/jddc_label_map.csv` 只收录
   **论文正文/示例对话可直接核对的 10 行**，其余以单行 `pending_corpus` 明示「待语料核对」，
   不猜测、不硬凑（方案 R3 的要求）。

## 五、对排期与后续动作的影响

- 方案 §六 的 P0 判据是「JDDC 不可用或标签不可映射 → 停手切方向一」。**判据已触发**，
  但触发的是「语料可得性」，不是「合规门禁机制」——后者（F-008–F-012，招牌部分）与语料无关，
  因此本次交付把 F-004–F-016 全部做实，并把 F-001/F-003 做成「一拿到文件就能跑通」的管道 + 留证。
- 需要人来做的动作（按代价从低到高）：
  1. 用能访问 AI Challenger 的网络/账号登录，下载 `train.json` 等原始文件 →
     `python scripts/fetch_jddc.py ingest --file <路径>` → `python scripts/clean_jddc.py --raw <路径> --n 2000`
     → `python scripts/verify_jddc_mapping.py`（自动产出未覆盖清单）；
  2. 若官方入口彻底下线：改用论文正文引用的二级来源（如各论文复现仓库）并**重新核对许可**；
  3. 若都拿不到：按方案预案，把评测集口径从「JDDC 真实语料」降级为「自标 golden set（当前状态）」，
     README 与本报告如实写明，不假装是真实语料评测。
