# 退货队列顾客风险提示

- 验证时间：2026-11-12
- 范围：后台退货列表内联展示顾客售后风险徽章与原因，客服处理退货时无需另开客户档案；顾客端不返回风险画像
- 迁移：无（风险画像实时计算，批量查询客户目录同源数据）

## 行为

1. 风险画像服务新增批量接口：一次查询订单、退货、取消换货、扣减申诉与顾客责任五组聚合，按客户 ID 映射风险视图，避免退货列表 N+1。
2. 后台退货列表（活跃/申诉/取件/状态/全部筛选）在同一次响应中返回 `customer_risk_level` 与 `customer_risk_reasons`；单条与管理端复用原有计算口径。
3. 退货卡片在顾客手机号后展示：
   - `高风险`：高风险顾客（红）；
   - `需关注`：需关注顾客（黄）；
   - 正常不显示徽章；最多展示前两条原因，完整原因见客户档案。
4. 顾客端退货接口仍走同一视图结构，但风险字段固定为 `null` / 空数组，不泄露内部画像。
5. 风险只提示，不改变退货审批、提案、AI 回复或自动分配；仍无按风险筛选、排序或自动拒绝。
6. 修复通知铃铛在“轮询先到、SSE 后到”时未读数重复 +1 的竞态：客户端按通知 ID 去重，已见 ID 不再递增未读。
7. E2E 返回流程不再依赖首页第一个商品的价格：质检扣减改为 1 元，并在开始前重置退货政策，避免共享库中高价/低价遗留商品造成零退款断言。

## 边界

- 风险信息最多展示两条原因，完整计数仍在客户档案；退货列表无按风险筛选/排序与导出。
- 批量查询对当前页客户一次聚合，但退货列表最多 100 条；客户量很大时仍需分页与索引优化。
- 风险阈值与窗口仍是固定常量，不按商家/类目配置；误报可能性与客户档案相同。
- 顾客端只是不返回风险字段，不改变接口结构；AI 与工单仍未使用风险画像。
- 通知未读竞态修复是客户端去重，服务端未读计数仍以数据库为准；极端跨标签页未读可能短暂不一致。
- E2E 共享开发库的历史商品与政策仍会影响依赖价格/库存的断言；本次仅加固了返回流程用例。
