# 人工售后动作：退款 / 补偿 / 改地址

- 验证时间：2026-11-04
- 范围：电话/线下协商场景下，店主按订单代顾客发起售后提案
- 接口：`POST /api/admin/action-proposals`（仅店主）

## 行为

1. 店主在后台「售后提案」页展开「代顾客发起售后动作」，选择退款 / 补偿 / 改地址。
2. 服务端校验订单归属商家、支付状态与金额上限，创建售后单 + `created_by=staff` 的待审提案。
   - 退款：金额可留空（全部可退）或部分金额；不超过剩余可退。
   - 补偿：金额必填，不超过 `COMPENSATION_MAX_CENTS`。
   - 改地址：需填新地址；订单必须处于待支付或已支付、未进入履约。
3. 创建后**不会直接执行**；店主仍需在提案列表点击「批准并执行」，走原有审批、执行、审计链路。
4. 提案列表显示「店主发起 / AI 提案」来源；退款/补偿写 `refunds` 账本，改地址写订单地址。
5. 顾客会收到提案执行/驳回站内通知；设置邮箱时同步邮件。

## 边界

- 创建与批准是两步，不直接执行资金动作；没有独立审批限额或双人复核。
- 无请求级幂等键：重复提交会生成多条待审提案；审批时按剩余可退金额拒绝超额，不会多退。
- 改地址只允许待支付/已支付未履约订单；已发货/签收需人工客服处理。
- 原因最长 1000 字，不支持附件；仅店主可用，客服账号返回 403。
